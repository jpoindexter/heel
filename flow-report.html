Summary

The flow breaks at its most important moment: after you ask Heel something, the answer appears below the visible area. In a measured run with 8 tasks, Claude's reply sat at y=528-705 while the visible content ended at y=416, so 0 px of it was on screen. The cause is structural: one fixed-size window (not resizable) holds a task list, a reply and a composer, and the reply is placed under the list. Fixing the layout (conversation first, tasks collapsible, resizable window) removes most of the "doesn't flow / can't resize / things don't expand" feeling. A second, smaller group of issues is in what the agent says versus what it did.

Flow: Open Heel, ask, act on tasks, configure

Pattern source: flow-app-shell + flow-ai-chat · Entry point: click Greg, Cmd+Shift+H, tray menu, or Dock icon

Steps

  1. 1Open the panel

    A fixed 380 x 620 window appears above Greg, right-aligned, with Close, Today / Settings tabs, and an empty-or-full body.

    Primary action: start typing → but the ask box is not focused; you must click it first

    Breaks: the window is not resizable (resizable:false in tauri.conf.json); on a 900 px-tall screen there is no room above Greg, so the panel sits over him.
  2. 2First run, no AI provider chosen

    The Now card says "Nothing queued yet." Chips and ask box look ready.

    Primary action: Plan / Stuck / type + Enter → fails with "Choose an AI provider in Settings first." + Open Settings

    Breaks: the screen looks ready but cannot work. The fix (Settings) is discovered only after a failed attempt.
  3. 3Ask or press a chip

    Send turns into "Thinking…" and chips that use the AI are disabled. Takes 5-14 s with Claude/Codex, about 70 s cold with a local model.

    Primary action: wait → reply appears

    Breaks: "Thinking…" and the reply render below the task list, outside the visible area. No stop button. No streaming. The screen looks frozen, then nothing visibly changes.
  4. 4Read what Heel did

    Reply text plus ✓ lines (Added "...", Focus started: ...). Only the latest reply is kept.

    Primary action: act on the first step → Now card

    Breaks: reply is off-screen with a full list; there is no history; the provider/model that answered is not shown; the reply said "Want to start a focus block?" while the ✓ line showed it had already started one.
  5. 5Manage tasks

    Now card (first task's next step), then up to 3 tasks with checkbox and remove; "N more" reveals the rest. Complete and remove show an 8 s Undo.

    Primary action: checkbox → task leaves the list, Undo toast

    Breaks: the Now card repeats the first task directly above it; the 2nd task is cut mid-URL; "5 more" is below the fold; "expanding" only lengthens a scroll area inside a fixed window.
  6. 6Park an idea

    Type text, press Park it. Toast: "Parked: ...". Empty box shows a hint and focuses the box.

    Primary action: Park it → idea saved

    Breaks: parked ideas are never shown again (the count is fetched but not displayed), cannot be undone, and have no way to become tasks even though the store supports promote.
  7. 7Settings, then back

    Brain: provider radios with status, model field, Test connection, Undo. Works well; error state with Try again.

    Primary action: choose provider → saved, toast with Undo

    Breaks (from the code, Panel.tsx renders one tab at a time; not run): switching to Settings unmounts Today, so a typed draft, the last reply and the expanded list are lost. This hits exactly the path "AI failed, Open Settings, fix, come back".

Open questions & parked items

  • Layout direction needs a decision: chat-first panel with a collapsible task drawer (recommended), or keep Today as is and only fix scrolling and resizing.
  • Size limits for a resizable panel (suggested: min 340 x 420, max 560 x 860, remembered per screen).
  • Should the AI be allowed to start or end focus sessions before the focus UI (S6) exists? Recommendation: no, remove those two actions until S6 ships.
  • Streaming replies: the Claude CLI supports a streaming output mode; Codex and local models need checking. Not built, not verified.
  • Not tested: screen readers, keyboard-only flow end to end, the real Tauri window at other sizes, display scaling on external monitors.
