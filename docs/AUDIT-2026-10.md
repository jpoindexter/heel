# Heel — full app audit (2026-10-15)

Scope: the packaged `Heel.app` (built from commit 70c8d84 + docs), plus the code behind it. Method: Nielsen's heuristics (usability-heuristics skill) plus the v0 done criterion in `PRD.md`. Severity 0–4 (4 = fix before anyone relies on it). "Evidence" says what I actually ran or read; anything I could not run is in the last section.

## Verdict
Heel is a good **thinking-and-focus** companion and a poor **task manager** today. The largest gaps for a real working day are not polish: you can't add a task without waiting for the AI, you can't edit one, and if the helper dies nothing brings it back. The interface is also bigger than it needs to be (your note).

## What is good (keep)
- Quiet by design: no sound, 3 nudges a day enforced by the helper, Off mode, Stop button that really stops.
- "Model proposes, app disposes": every write has a receipt and an Undo.
- Focus check-in quotes your goal verbatim and has no wrong answer.
- Secrets handling: helper token file is mode 0600; Gmail secrets go to the Keychain on stdin; a pre-commit scan blocks leaks.
- Packaged app starts and stops its own helper cleanly; conversation survives restart.

## Not verified (honest limits)
VoiceOver; a second monitor; the real macOS "Reduce motion" setting; Gmail against real Google; the mic bug (B1) — needs your A/B test; behaviour on a Mac without Node; long-running (days) memory growth; battery impact beyond the CPU sample; sleep/wake recovery of the helper.
